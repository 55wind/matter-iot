# 노트북 세팅 · 에이전트 지침

새 노트북에서 시연을 준비하는 Claude 에이전트(또는 팀원)가 위에서부터 순서대로 따라 하는 문서입니다. 최종심사는 10/15(목) 12:00~18:00입니다.

## 먼저 알아둘 것

- DK에는 시연용 펌웨어가 이미 들어 있고 SmartThings에 등록돼 있습니다. 등록 정보는 DK 안에 저장되므로, 노트북을 바꿔도 USB로 꽂기만 하면 됩니다.
- **시연만 할 거라면 1~5단계만 하면 됩니다.** 6단계(펌웨어 빌드 환경)는 코드를 고쳐야 할 때만 합니다. SDK 설치에 수 GB, 30분 이상 걸립니다.
- 노트북이 하는 일은 두 가지입니다. 시연 화면 `sim/sim.html`을 Chrome으로 띄우는 것, DK와 USB 시리얼(115200)로 값을 주고받는 것.
- `sim.html`은 인터넷 없이 돕니다. 글꼴도 저장소 안(`sim/fonts`)에 있습니다.
- 프로젝트 개요와 판단 규칙은 [`README.md`](../README.md), 화면 읽는 법과 대사는 [`시연_방안.md`](시연_방안.md)에 있습니다.

## 에이전트가 지킬 규칙

1. **콘솔 창을 화면에 띄우지 않는다.** 사용자의 절대 규칙입니다.
   - Bash 안에서 `powershell`, `cmd`, `cmd //c`, `start`, `explorer`를 실행하지 않는다. 프로세스 확인은 `ps -W`처럼 bash 안에서 끝나는 명령으로 한다.
   - PowerShell 도구도 꼭 필요할 때가 아니면 쓰지 않는다.
   - Python에서 외부 프로그램을 실행할 때는 `creationflags=subprocess.CREATE_NO_WINDOW`를 넣는다(`os.system` 금지).
   - 오래 걸리는 작업은 Bash 도구의 `run_in_background`로만 돌린다. 새 창이나 새 터미널을 여는 방식은 쓰지 않는다(`nrfutil ... toolchain launch --terminal`도 쓰지 않는다).
   - 계속 도는 Python 작업은 반드시 `pythonw.exe`로 돌린다.
   - 서브에이전트에게 일을 맡길 때도 이 규칙을 프롬프트에 넣는다.
2. 웹 브라우징은 gstack `/browse`로 한다. `mcp__claude-in-chrome__*` 도구는 쓰지 않는다.
3. Chrome 안의 조작(포트 연결, 시나리오 버튼)은 사용자가 직접 한다. Web Serial은 사람이 포트를 골라야 열린다. 에이전트는 주소와 누를 버튼만 안내한다.
4. 다음은 **반드시 사용자에게 먼저 묻는다.** 등록이 풀려 휴대폰으로 다시 등록해야 하는 작업들이다.
   - `west flash --erase`, `nrfutil device erase`
   - SmartThings 앱에서 기기 삭제, 스테이션 초기화
5. commit, push는 사용자가 요청할 때만 한다.
6. 시연 설명을 쓰거나 말할 때 "센서값은 가상 침실 모델이 만들고, 판단·예측·학습·Matter 노출은 보드 안에서 한다"를 지킨다. 센서가 실제로 붙어 있다고 하지 않는다.

## 1단계 · 저장소 받기 (필수)

저장소 `github.com/55wind/matter-iot`는 **비공개**입니다. 노트북의 GitHub 계정이 55wind가 아니면 저장소 Settings → Collaborators에서 먼저 초대를 받아야 합니다.

```bash
gh auth status        # 로그인 안 돼 있으면 사용자에게 `! gh auth login` 실행을 부탁한다
git clone https://github.com/55wind/matter-iot.git /c/matter-iot
git -C /c/matter-iot log -1 --oneline
```

- 경로는 `C:\matter-iot`처럼 **띄어쓰기와 한글이 없는 곳**으로 합니다. 6단계 빌드를 그대로 할 수 있습니다. (개발 PC는 경로에 띄어쓰기가 있어 junction `D:\ORCA\matter-iot`를 거쳐 빌드했습니다.)
- `gh`가 없으면 `git clone`만 해도 Git Credential Manager가 로그인 창을 띄웁니다. 로그인은 사용자가 합니다.

## 2단계 · DK 연결과 포트 확인 (필수)

1. DK의 **DEBUGGER(J-Link) 쪽 USB-C**를 노트북에 꽂고 DK 전원 스위치를 켭니다. 데이터 전송이 되는 케이블이어야 합니다.
2. 릴레이 배선이 그대로인지 사용자에게 확인을 부탁합니다. IN1 → **P1.20**(선풍기), IN2 → **P1.21**(가습기), VCC → 5V, GND → GND. 릴레이는 LOW에서 켜집니다.
3. 포트를 확인합니다. 창 없이 bash 안에서 끝납니다.

   ```bash
   ls /dev/ttyS*        # DK 꽂기 전과 후를 비교. /dev/ttySN = COM(N+1)
   ```

   nrfutil이 있으면 더 정확합니다.

   ```bash
   mkdir -p ~/bin
   curl -L -o ~/bin/nrfutil.exe "https://files.nordicsemi.com/artifactory/swtools/external/nrfutil/executables/x86_64-pc-windows-msvc/nrfutil.exe"
   ~/bin/nrfutil.exe install device
   ~/bin/nrfutil.exe device list
   ```

   `Board version PCA10184` 아래에 COM 포트가 **2개**(vcom 0, vcom 1) 나옵니다. 개발 PC에서는 **vcom 1 쪽(COM3)**이 시연용 포트였습니다. 노트북에서는 번호가 달라지니, 3단계에서 안 되면 다른 쪽을 고릅니다.
4. 포트가 하나도 안 보이면 J-Link 드라이버가 없는 것입니다. 사용자에게 **nRF Connect for Desktop**(설치 중 J-Link/SEGGER 설치를 물으면 동의) 또는 **SEGGER J-Link Software** 설치를 부탁합니다. 그래픽 설치 프로그램이라 사용자가 직접 합니다.

## 3단계 · 시연 화면 띄우기 (필수)

Chrome에서 파일을 바로 열면 Web Serial이 막힐 수 있어서 로컬 서버로 엽니다.

**에이전트가 할 일.** Bash 도구에서 `run_in_background: true`로 실행합니다. `pythonw`는 콘솔이 없으니 출력을 반드시 파일로 돌립니다.

```bash
cd /c/matter-iot && pythonw -m http.server 8000 --bind 127.0.0.1 --directory sim > "$TEMP/sim_http.log" 2>&1
```

확인:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/sim.html    # 200이면 정상
```

- Python이 없으면 `winget install -e --id Python.Python.3.12`로 설치한 뒤 다시 합니다.
- 8000번이 이미 쓰이고 있으면 다른 번호(예: 8765)를 쓰고 사용자에게 바뀐 주소를 알려 줍니다.
- 서버를 끝낼 때는 `ps -W | grep -i pythonw`로 찾아 `kill`합니다.

**사용자가 할 일.**

1. Serial Terminal, VS Code 시리얼 모니터 등 DK 포트를 쓰는 프로그램을 모두 닫습니다.
2. Chrome(또는 Edge)에서 `http://localhost:8000/sim.html`을 열고 F11로 전체 화면을 켭니다.
3. **포트 연결** → DK 포트 선택 → 오른쪽 위가 **"보드가 판단 중"**으로 바뀌면 성공입니다. "보드 미연결 · 화면 안 계산"이면 포트를 다시 고릅니다.

## 4단계 · Matter 연결 확인 (필수)

1. 스마트싱스 스테이션 전원을 넣고, 휴대폰 SmartThings 앱에서 스테이션이 **온라인**인지 봅니다.
2. 행사장에서는 앱에서 스테이션 Wi-Fi를 행사장 Wi-Fi나 백업 핫스팟으로 바꿉니다. 방법은 [장비 테스트 설명서](침실%20환경%20면역%20방어%20노드%20·%20장비%20테스트%20설명서.md) 2단계 6번입니다. 5G Wi-Fi와 로그인 화면이 뜨는 Wi-Fi는 안 됩니다.
3. 시연 화면 오른쪽 위 **"Matter 연동"** 칸에 허브 보고와 수신 확인 횟수가 올라오면 정상입니다.
4. 앱에서 선풍기(EP1)와 가습기(EP5)를 켜고 꺼 보고, 릴레이 딸깍과 DK 불빛(LED1 선풍기, LED2 가습기)이 맞는지 봅니다. 앱으로 직접 조작하면 노드가 30분(화면 시각) 동안 그 조작을 존중합니다.

허브가 안 보여도 판단과 릴레이 제어는 보드 안에서 계속됩니다. 앱에서 기기를 지우지 않습니다(규칙 4).

## 5단계 · 리허설 확인 (필수)

**▶ 한파의 밤**을 눌러 약 60초(1초 = 10분) 동안 아래 순서가 나오는지 사용자와 함께 확인합니다. 개입 시각은 실행마다 조금씩 다르고 순서는 같습니다.

| 화면 시각 | 기대 결과 |
| --- | --- |
| 22:00 | 가습기 ON (딸깍) |
| 22:40 무렵 | 가습기 OFF, 침구 습도가 올라 취침 감지 |
| 01:00~03:00 | 벽 표면 75%에서 가습 OFF, 이어서 선풍기 ON (딸깍). 선풍기 효과 학습 +3℃ 안팎 |
| 그다음 | 선풍기를 켠 채 가습 재개 (판단 이유에 `band_by_fan`) |
| 07:35~07:50 | 기상 감지, 침구 건조 (가습 정지, 선풍기 ON) |
| 끝 | 누적 위험 시간 우리 노드 **0분** vs 일반 가습기 **약 8시간대** |

- 매번 끝나면 **⟲ 처음으로**를 누릅니다. 보드의 누적 위험 시간과 학습값까지 초기화됩니다.
- DK USB를 뽑았다 꽂은 뒤 1분 안에 포트를 다시 연결할 수 있는지도 한 번 해 봅니다.
- 화면 녹화(Windows 키 + Alt + R)로 백업 영상을 하나 남겨 두면 라이브가 실패할 때 틉니다.

## 6단계 · 펌웨어 빌드 환경 (선택, 코드를 고칠 때만)

nRF Connect SDK **v3.4.1**, 보드 타깃 **`nrf54lm20dk/nrf54lm20b/cpuapp`**입니다(칩이 B라서 `nrf54lm20a`가 아닙니다).

1. 2단계의 nrfutil을 설치하고, SDK 관리 도구와 SDK를 받습니다. 오래 걸리니 `run_in_background`로 돌립니다.

   ```bash
   N=~/bin/nrfutil.exe
   "$N" install sdk-manager
   "$N" sdk-manager config install-dir set 'C:\ncs'
   "$N" sdk-manager install v3.4.1
   ```

2. 빌드합니다. 노트북 메모리가 빠듯하면 `-o=-j4`로 동시 컴파일 수를 줄입니다.

   ```bash
   N=~/bin/nrfutil.exe; export ZEPHYR_BASE='C:\ncs\v3.4.1\zephyr'
   "$N" sdk-manager toolchain launch --ncs-version v3.4.1 --chdir 'C:\matter-iot\firmware\light_bulb' -- west build -b nrf54lm20dk/nrf54lm20b/cpuapp -d build -o=-j4 .
   ```

3. 플래시는 **`--erase` 없이** 합니다. 이러면 보통 SmartThings 등록이 유지됩니다. 끝난 뒤 앱에서 기기가 그대로 동작하는지 확인하고, 안 되면 사용자에게 알립니다.

   ```bash
   "$N" sdk-manager toolchain launch --ncs-version v3.4.1 --chdir 'C:\matter-iot\firmware\light_bulb' -- west flash -d build
   ```

4. 엔드포인트(`light_bulb.zap`)를 바꿨다면 재등록이 필요합니다. **사용자에게 먼저 묻고** 앱에서 기기 삭제 → `west flash -d build --erase` → 앱에서 다시 등록합니다. 개발용 페어링 코드는 `34970112332`입니다.

플래시 오류에 J-Link 얘기가 나오면 SEGGER J-Link Software가 없는 것이니 2단계 4번처럼 사용자에게 설치를 부탁합니다.

## 문제가 생기면

| 증상 | 대응 |
| --- | --- |
| 포트 연결 실패 | DK 포트를 쓰는 다른 프로그램을 닫고 다시 연결. 다른 COM 포트도 시도 |
| 버튼을 눌러도 반응 없음 | 파일을 직접 연 경우. 3단계 로컬 서버 주소로 열기 |
| "Matter 연동" 칸이 안 올라감 | 스테이션 전원과 Wi-Fi 확인. 판단과 딸깍은 계속되니 시연은 진행 가능 |
| 앱에서 노드가 오프라인 | 스테이션 Wi-Fi를 백업 핫스팟으로 변경. 안 되면 녹화 영상 |
| 보드 없이 시연해야 함 | 포트 연결 없이 진행하면 같은 로직이 화면 안에서 돕니다. 이때는 "보드가 판단 중"이라고 말하지 않습니다 |

더 자세한 장애 대응은 [`시연_방안.md`](시연_방안.md)의 장애 대응, [장비 테스트 설명서](침실%20환경%20면역%20방어%20노드%20·%20장비%20테스트%20설명서.md)의 문제 해결표에 있습니다.

## 끝나면 사용자에게 보고할 것

- 저장소 경로와 최신 커밋 (`git log -1 --oneline`)
- DK 포트 번호 (예: COM5, vcom 1)
- 로컬 서버 주소와 백그라운드 작업 여부
- 3·4·5단계 결과. 화면에서 직접 본 것은 사용자가 말해 준 내용으로 적는다
- 안 된 것, 건너뛴 것
