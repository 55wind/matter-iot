# 시연 방안 · 가상 침실 + 판단 노드

## 무엇을 보여주는가

1. 방 습도계는 그대로인데 **벽 표면 습도만 오른다** (실내 40% vs 벽 표면 77%)
2. **판단은 보드 안에서** 한다 (표면 습도, 절대습도, 예측, 선풍기 효과 학습, 누적 위험 시간)
3. 개입이 **Matter로 나간다** (릴레이 딸깍 2개 + SmartThings 앱의 가습기·선풍기·벽 표면 습도)
4. **개입 결과가 다시 환경을 바꾼다** (선풍기 → 벽 표면 +3.4℃ → 표면 습도 하락 → 가습 재개)

말할 때 지킬 것: "센서값은 가상 침실 모델이 만들고, 판단·예측·학습·Matter 노출은 전부 이 보드 안에서 합니다." 센서가 실제로 붙어 있다고 말하지 않습니다.

## 장비 배치

- 모니터(또는 노트북): `sim/sim.html` 하나만 띄움 (Chrome 전체 화면 F11). 휴대폰은 보여주지 않음
- DK: USB로 노트북에 연결. 릴레이 IN1(P1.20) = 선풍기, IN2(P1.21) = 가습기. 딸깍 소리와 DK 불빛이 실물 증거
- 스테이션: 켜 두면 화면 오른쪽 위 "Matter 연동" 칸에 허브 보고·수신 확인이 실시간으로 올라감

## 화면 읽는 법

| 칸 | 보여주는 것 |
| --- | --- |
| 왼쪽 위 방 그림 | 가상 침실. 보드가 가습기를 켜면 수증기, 선풍기를 켜면 날개가 돌고 바람이 벽으로 감. 벽 표면 띠 색 = 표면 습도 |
| 가운데 위 | 실내 습도 vs 벽 표면 습도, 가습기·선풍기 상태, 예측, 학습값, 누적 위험 시간 비교 |
| 오른쪽 위 Matter 연동 | 노드가 Matter 속성으로 내보내는 EP1~EP5 값 + SmartThings 허브로 보낸 보고(ReportData) 횟수와 허브의 수신 확인·응답 시간 |
| 왼쪽 아래 그래프 | 밤새 실내(회색)·벽 표면(파랑)·일반 가습기였다면(빨강 점선). 파란 띠 = 선풍기 가동 |
| 가운데 아래 표 3 | 지금 허용되는 실내 습도 구간. 점선 = 선풍기가 없을 때 |
| 오른쪽 아래 판단 기록 | 노드가 보낸 판단 이유를 문장으로 |

## 시나리오 (배속 1초 = 10분, 약 60초)

개입 시각은 실행마다 몇십 분(화면에서 몇 초)씩 달라질 수 있습니다. 순서는 항상 같습니다.

| 화면 시각 | 경과 | 일어나는 일 | 말할 것 |
| --- | --- | --- | --- |
| 22:00 | 0초 | 건조한 방(35%). 가습기 ON (딸깍) | "겨울 침실은 건조해서 점막 방어를 위해 가습이 필요합니다(절대습도 6 g/㎥)" |
| 22:45 | 4초 | 절대습도 8 → 가습기 OFF | |
| 00:25 | 14초 | 다시 가습 ON | "바깥이 영하로 내려가며 벽이 식습니다" |
| 01:00~03:00 | 18~30초 | **표면 75% → 가습 OFF** (실내는 44%). 그래도 오르면 **0.5초 뒤 선풍기 ON (딸깍)** | "방 습도계는 44%로 평온하지만 벽 표면은 75%입니다. 가습을 멈추고 선풍기로 벽 표면을 데웁니다" + 오른쪽 위 Matter 칸의 허브 수신 확인을 가리킴 |
| 선풍기 ON 직후 | | 노드가 선풍기 효과 학습: 벽 +3℃ 안팎 | "노드가 이 집 벽에서 선풍기가 몇 도를 올리는지 스스로 잽니다" |
| 그다음 | | **선풍기를 켠 채 가습 재개** (로그에 `band_by_fan`) | "선풍기가 되찾은 구간(표 3 띠) 안에서 가습을 계속합니다. 두 목표를 동시에 지킵니다" |
| 07:30 무렵 | 55~59초 | 아침, 벽이 데워져 선풍기 OFF | |
| 끝 | | 누적 위험 시간 **우리 0분 vs 일반 가습기 약 8시간 40분**, 일반 가습기 표면 119% (결로) | "방 습도계로는 못 잡는 위험을 임계 전에 스스로 막았습니다" |

화면 오른쪽 "표 3" 띠: 파란 칸이 지금 허용되는 실내 습도, 점선 칸이 선풍기가 없을 때의 허용 범위, 검은 막대가 현재 실내 습도입니다.

| 2:30~3:00 | 누적 위험 시간 비교로 마무리 |

## 장애 대응

- 포트 연결 실패: Serial Terminal, VS Code 시리얼 창을 닫고 다시 연결. 그래도 안 되면 연결 없이 진행 → 화면에 "보드 미연결 · 화면 안 계산"이 뜨고 같은 로직이 화면 안에서 돕니다. 이 경우 "보드가 판단 중"이라고 말하지 않습니다.
- Matter 칸에 허브 보고가 안 올라감: 스테이션 전원·Wi-Fi 확인. 판단과 딸깍은 허브 없이도 계속됩니다 ("클라우드가 끊겨도 방어는 멈추지 않는다"로 활용).
- 심사위원이 앱에서 직접 끄고 켜면: 노드가 그 조작을 받아들이고 30분(화면 시각) 동안 존중합니다. 벽 표면이 80%를 넘으면 방어를 우선합니다.
- 리허설이 끝날 때마다 ⟲ 처음으로를 누릅니다 (보드의 누적 위험 시간과 학습값도 초기화됨).
