남은 시간은 짧습니다. 오늘은 10/12(월)이고, 발표자료 PDF는 10/13(화) 15:00까지, 최종심사는 10/15(목)입니다.

1. 단계마다 끝에 있는 \*\*"이렇게 되면 성공"\*\*을 눈으로 확인한 뒤에만 다음 단계로 넘어갑니다.

4. 1단계(노트북 설치), 2단계(스테이션), 4단계(릴레이 배선)는 서로 상관없으니 세 명이 나눠서 동시에 해도 됩니다.

**용어 풀이** · 모르는 말이 나오면 여기로 돌아오세요.

| 말 | 쉬운 뜻 |
| --- | --- |
| DK (nRF54LM20 DK) | 우리 제품의 두뇌 역할을 하는 개발 보드. 받은 보드 그 자체 |
| 펌웨어 | DK 안에서 돌아가는 프로그램 |
| 빌드 (Build) | 코드를 DK가 알아듣는 파일로 바꾸는 작업. 버튼 하나로 함 |
| 플래시 (Flash) | 빌드한 파일을 USB로 DK에 집어넣는 작업. 버튼 하나로 함 |
| 시리얼 터미널 | DK와 글자로 대화하는 창. DK가 보내는 메시지가 보이고, 명령을 쳐서 보낼 수 있음 |
| COM 포트 | 노트북이 DK를 부르는 이름 (예: COM5) |
| 릴레이 | 신호를 받으면 "딸깍" 하고 켜지는 전기 스위치 |
| 핀 / GPIO 핀 | 보드 가장자리에 튀어나온 작은 금속 막대. GPIO 핀은 그중 신호를 내보낼 수 있는 핀 |
| 점퍼선 | 핀끼리 잇는 색깔 전선. 끝이 구멍이면 "암", 뾰족한 핀이면 "수" |
| Matter | 스마트홈 기기들이 회사와 상관없이 서로 통하게 하는 공통 규칙 |
| Thread | Matter 기기가 쓰는 저전력 무선 통신. Wi-Fi와는 다른 것 |
| 스마트싱스 스테이션 | Thread 신호를 Wi-Fi로 이어 주는 삼성 허브. 산 네모난 기기 |
| 커미셔닝 | 새 기기를 앱에 등록하는 과정 |
| VS Code | 코드를 열고 고치고 빌드하는 프로그램 |
| SDK | DK용 개발 도구 묶음. VS Code에서 버튼으로 설치함 |

## 준비물과 작업대

아래 물건을 책상 위에 꺼내 놓고, 하나씩 확인하며 체크하세요.

- [ ] **nRF54LM20 DK** 1개: 보드에 USB-C 포트가 2개 있으면 "DEBUGGER" 또는 "J-Link"라고 적힌 쪽을 찾아 둡니다. LED1, LED2라고 적힌 작은 불빛 위치도 봐 둡니다.
- [ ] **USB-C 케이블** 2개: 데이터 전송이 되는 케이블이어야 합니다. 휴대폰 충전기에 딸려 온 얇은 케이블은 충전만 되는 경우가 있습니다. 1개는 예비입니다.
- [ ] **스마트싱스 스테이션**과 전원 어댑터: 어댑터가 없으면 USB-C 휴대폰 충전기를 씁니다.
- [ ] **2채널 릴레이 모듈** 1개: 파란 상자 2개가 달린 보드입니다.
- [ ] **점퍼선 세트** 1개: 이번에는 양쪽 끝이 구멍인 "암-암" 4가닥만 씁니다.
- [ ] **노트북** 1대: Chrome 브라우저가 깔려 있어야 합니다.
- [ ] **휴대폰 A** (시연용): SmartThings 앱을 깔고, 블루투스와 위치를 켭니다.
- [ ] **휴대폰 B** (예비): 행사장 Wi-Fi가 막힐 때 핫스팟으로만 씁니다.
- [ ] **멀티탭** 1개

**책상 배치**는 실제 시연 때와 똑같이 합니다. 노트북 오른쪽에 DK, DK 오른쪽에 릴레이를 놓고, 스테이션은 DK에서 2\~3m 안에 둡니다. 선풍기는 쓰지 않고, **DK의 LED2 불빛과 릴레이의 딸깍 소리**로 선풍기가 켜진 것을 보여줍니다.

## 1단계 · 노트북에 도구 설치하고 보드 확인하기 (약 1\~2시간)

**목표:** 노트북에서 만든 시험 프로그램을 DK에 넣어서, DK의 불빛이 깜빡이게 만드는 것입니다. 설치가 오래 걸리니 기다리는 동안 다른 팀원은 2단계와 4단계를 하세요.

**가. 프로그램 설치하기**

1. 브라우저에서 \*\*"ㅊ"\*\*을 검색해 Nordic 공식 사이트에서 Windows용을 받아 설치합니다. 설치 중에 "J-Link" 또는 "SEGGER" 설치를 물어보면 모두 **설치·동의**를 누릅니다.
2. nRF Connect for Desktop을 실행하면 앱 목록이 나옵니다. **Board Configurator**와 **Serial Terminal** 옆의 **Install**을 누릅니다.
3. **VS Code**를 설치합니다(code.visualstudio.com). 실행한 뒤 왼쪽 세로 막대에서 \*\*네모 4개 모양 아이콘(확장)\*\*을 누르고, 검색창에 **nRF Connect for VS Code Extension Pack**을 입력해 **Install**을 누릅니다.
4. 왼쪽 세로 막대에 **nRF Connect 아이콘**이 새로 생깁니다. 누르면 **Install Toolchain**과 **Install SDK** 버튼이 보입니다. 둘 다 누르고, 목록에서 \*\*가장 위에 있는 최신 버전(v3.3 이상)\*\*을 고릅니다. 30분\~1시간 걸립니다.

**나. 보드 연결하고 설정하기**

5. USB-C 케이블로 DK의 **DEBUGGER(또는 J-Link) 쪽 포트**와 노트북을 잇고, DK의 전원 스위치를 켭니다. 보드에 불이 하나 이상 켜지면 됩니다.
6. nRF Connect for Desktop에서 **Board Configurator**를 엽니다. 왼쪽 위 **Select device**에서 DK를 고르고, **VDD** 항목을 **3.3V**로 바꾼 뒤 오른쪽 아래 **Write config**를 누릅니다. 이걸 안 하면 4단계 릴레이가 동작하지 않습니다.

**다. 시험 프로그램 넣기**

7. VS Code의 nRF Connect 화면에서 **Create a new application** → **Copy a sample**을 누르고, 검색창에 **blinky**를 입력해 **Blinky**를 고릅니다. 저장 위치는 **한글과 띄어쓰기가 없는 폴더**로 합니다(예: `C:\ncs-work\blinky`). 한글 경로는 빌드 오류의 가장 흔한 원인입니다.
8. 왼쪽 **APPLICATIONS** 목록에 blinky가 생깁니다. 그 아래 **Add build configuration**을 누르고, **Board target**에서 `nrf54lm20dk/nrf54lm20a/cpuapp`를 골라 **Build Configuration**을 누릅니다. 아래쪽 창에 글자가 한참 지나가고 몇 분 뒤 끝납니다.
9. 왼쪽 **ACTIONS** 목록에서 **Flash**를 누릅니다. 1분 안에 끝납니다.

명령 창에 익숙한 사람만 아래 명령을 써도 됩니다. 7\~9번과 같은 일을 합니다.

```bash
west build -b nrf54lm20dk/nrf54lm20a/cpuapp zephyr/samples/basic/blinky -p
west flash
```

**라. DK와 대화하는 창 열기**

10. nRF Connect for Desktop에서 **Serial Terminal**을 엽니다. 장치를 고르면 포트(예: COM5, COM6)가 여러 개 보일 수 있습니다. 속도는 **115200**으로 두고 하나씩 열어 보면서, **글자가 나오는 포트 번호를 종이에 적어 둡니다.** 이후 단계에서 계속 씁니다.

**이렇게 되면 성공:** DK의 불빛 하나가 1초마다 켜졌다 꺼졌다를 반복합니다.

**안 되면:** 보드 목록에 nrf54lm20dk가 없으면 4번에서 고른 버전이 낮은 것이니 최신으로 다시 설치합니다. DK가 아예 안 잡히면 케이블을 다른 것으로 바꿔 보세요.

## 2단계 · 스마트싱스 스테이션 등록하기 (약 30분)

**목표:** 스테이션을 SmartThings 앱에 등록해서, 앱에서 "온라인"으로 보이게 하는 것입니다. 스테이션은 DK의 무선 신호(Thread)를 휴대폰 앱까지 전달하는 중계기입니다.

지금은 **집이나 연구실 Wi-Fi**로 등록하고, 심사 당일에 **행사장 Wi-Fi**로 바꿉니다. 앱이 인터넷을 거쳐 스테이션을 제어하므로, 어떤 Wi-Fi든 인터넷이 되어야 합니다.

1. **주최 측에 메일로 미리 물어봅니다** (recurit@kashi.or.kr). 물어볼 것은 네 가지입니다: Wi-Fi 이름, 비밀번호, 2.4GHz를 지원하는지, 접속할 때 로그인 화면이 뜨는지. 로그인 화면이 뜨는 Wi-Fi에는 스테이션이 연결되지 않습니다.
2. **휴대폰 A**에 SmartThings 앱을 깔고 삼성 계정으로 로그인합니다. 당일 누구 폰으로든 시연할 수 있게 **팀 공용 계정** 하나를 만들어 쓰는 것을 권합니다. 블루투스와 위치(GPS)를 켭니다.
3. 스테이션에 전원을 꽂습니다. 앱 오른쪽 위 **+** → **기기 추가** → **스마트싱스 스테이션**을 고르거나, 스테이션 바닥의 QR 코드를 찍습니다. 화면 안내를 따르다가 Wi-Fi를 고르는 화면에서 **집이나 연구실 Wi-Fi**를 고릅니다. 이름에 "5G"가 붙은 Wi-Fi는 피하세요.
4. "업데이트"가 뜨면 끝날 때까지 기다립니다. 몇 분 걸리니 이 사이에 다른 단계를 하세요.
5. 앱에서 스테이션을 눌러 설정(톱니바퀴)으로 들어가, **Thread** 라는 글자가 들어간 메뉴가 있는지 확인합니다.
6. **(3단계를 끝낸 뒤에 할 것) Wi-Fi 바꾸기 연습:** 스테이션 설정에서 Wi-Fi를 다른 것(ipTIME 공유기나 휴대폰 B 핫스팟)으로 바꿔 봅니다. 바꾼 뒤에도 3단계에서 등록한 DK가 앱에 그대로 있고 켜고 끄기가 되는지, 몇 분 걸렸는지 적어 둡니다. 당일 행사장에서 똑같이 하게 됩니다.

**이렇게 되면 성공:** 앱에서 스테이션이 "온라인"으로 보입니다.

**알아둘 것:** 6번에서 Wi-Fi를 바꾸는 메뉴가 없어 스테이션을 초기화해야 한다면, DK도 3단계부터 다시 등록해야 할 수 있습니다. 행사장 Wi-Fi가 막히면 휴대폰 B의 핫스팟을 대신 씁니다.

## 3단계 · DK를 SmartThings 앱에 등록하기 (약 1\~2시간, 가장 중요)

**목표:** 휴대폰 앱의 켜기·끄기 버튼을 누르면 DK의 불빛이 켜지고 꺼지게 만드는 것입니다. 이게 되면 "DK → 스테이션 → 앱"으로 이어지는 Matter 길이 뚫린 겁니다. **이 단계가 안 되면 나머지가 의미 없으니 가장 먼저 해결하세요.**

여기서는 Nordic이 미리 만들어 둔 \*\*전구 예제(light\_bulb)\*\*를 그대로 씁니다. 앱에서 전구를 켜면 DK 불빛이 켜지는 예제입니다.

1. 1단계 7\~8번과 똑같이 하되, 검색창에 **light\_bulb**를 입력해 **Matter: Light bulb**를 고릅니다. 저장 위치는 `C:\ncs-work\light_bulb`처럼 한글 없는 곳으로 합니다. 보드도 똑같이 `nrf54lm20dk/nrf54lm20a/cpuapp`를 고르고 빌드합니다. **처음 빌드는 10\~20분** 걸리니 기다립니다.
2. 빌드가 끝나면 ACTIONS의 **Flash 옆 화살표나 점 세 개**를 눌러 **Erase and Flash to Board**를 고릅니다. DK에 남아 있던 예전 정보를 지우고 넣는 것입니다.

명령 창을 쓴다면 아래와 같습니다.

```bash
west build -b nrf54lm20dk/nrf54lm20a/cpuapp nrf/samples/matter/light_bulb -p
west flash --erase
```

3. Serial Terminal에서 1단계에서 적어 둔 포트를 엽니다. DK의 **RESET 버튼**을 한 번 누르면 글자가 쭉 나옵니다. 그중 `https://project-chip.github.io/connectedhomeip/qrcode.html?data=MT:`로 시작하는 줄을 찾아 **통째로 복사해 노트북 브라우저 주소창에 붙여 넣으면 QR 코드**가 뜹니다. 이 화면을 켜 둡니다.
4. 같은 글자들 중에 **Manual pairing code**라는 숫자도 적어 둡니다. 개발용 기본값이면 보통 `34970112332`입니다. QR이 안 찍힐 때 씁니다.
5. 휴대폰 A가 스테이션과 **같은 Wi-Fi**에 연결돼 있는지, 블루투스가 켜져 있는지 확인합니다.
6. SmartThings 앱 오른쪽 위 **+** → **기기 추가** → **Matter**(또는 "파트너 기기" 안의 Matter)를 고르고, 노트북 화면의 QR을 찍습니다. QR이 안 되면 "코드 입력"을 골라 4번 숫자를 넣습니다.
7. "인증되지 않은 기기"라는 경고가 나오면 **계속**을 누릅니다. 앱이 아예 등록을 거부하면 SmartThings의 개발자 모드를 켜야 합니다. 이때는 박건우에게 넘기세요.
8. 기기를 못 찾는다고 나오면, DK가 등록 대기 시간을 넘긴 것입니다. DK의 버튼(예제 설명서의 "commissioning" 버튼)을 누르거나 RESET을 누른 뒤 6번을 다시 합니다.
9. 등록이 끝나면 앱에 전구 모양 기기가 생깁니다. 눌러서 켜기·끄기를 해 봅니다.

**이렇게 되면 성공:** 앱에서 켜기를 누르면 DK의 불빛이 켜지고, 끄기를 누르면 꺼집니다.

**처음부터 다시 등록해야 할 때:** 앱에서 그 기기를 길게 눌러 삭제하고, 2번처럼 **Erase and Flash to Board**로 다시 넣은 뒤 3번부터 합니다. 6단계에서 프로그램을 크게 바꾸면 이 과정이 필요합니다.

## 4단계 · 릴레이 꽂기 (약 30분)

**목표:** DK가 신호를 보내면 릴레이가 "딸깍" 소리를 내고 릴레이의 작은 불빛이 켜지게 만드는 것입니다. 이 딸깍이 실제 제품에서 선풍기를 켜는 순간을 대신합니다. 다루는 전기는 USB 5V뿐이라 감전 위험은 없지만, **선은 꼭 DK 전원 스위치를 끈 상태에서** 꽂습니다.

**가. 핀 이름 찾기**

1. **DK**의 가장자리 핀 옆이나 보드 뒷면에 작은 글씨로 핀 이름이 인쇄돼 있습니다. **5V**(또는 VDD5, VBUS), **GND**를 찾아 둡니다. 휴대폰 사진으로 크게 찍어 보면 편합니다.
2. 같은 곳에서 `P1.04`처럼 **P숫자.숫자** 모양으로 적힌 핀 중 두 개를 고릅니다. 이게 GPIO A, GPIO B입니다. LED, 버튼, 디버거라고 적힌 핀 근처는 피하고, 고른 두 핀 이름을 종이에 적습니다. 어떤 핀이 비어 있는지 모르겠으면 Nordic 사이트의 nRF54LM20 DK 사용자 가이드에서 핀 표를 확인합니다.
3. **릴레이** 보드 한쪽 끝에 핀 4개가 있고 **DC+, DC-, IN1, IN2**라고 적혀 있습니다(VCC, GND라고 적힌 제품도 있습니다).
4. 릴레이 보드 위에 \*\*H와 L이 적힌 작은 핀과 그걸 덮은 검은 캡(점퍼 캡)\*\*이 있습니다. 캡을 뽑아서 **H 쪽**에 꽂습니다. 채널이 2개면 둘 다 H로 합니다.

**나. 점퍼선 꽂기 (암-암 4가닥)**

헷갈리지 않게 **색을 정해서** 꽂으세요. 위 연결도 그림과 똑같습니다.

| 순서 | 점퍼선 색 (권장) | DK 쪽 | 릴레이 쪽 |
| --- | --- | --- | --- |
| 1 | 빨강 | 5V | DC+ (VCC) |
| 2 | 검정 | GND | DC- (GND) |
| 3 | 파랑 | GPIO A (적어 둔 첫 번째 핀) | IN1 |
| 4 | 아무 색 | GPIO B (적어 둔 두 번째 핀) | IN2 |

릴레이 반대쪽의 나사 구멍 3개(COM, NO, NC)에는 **아무것도 꽂지 않습니다.**

**다. 딸깍 시험하기**

DK가 2초마다 GPIO A로 신호를 보내게 1단계의 blinky를 살짝 고칩니다.

5. VS Code 왼쪽 탐색기에서 blinky 폴더를 열고, 폴더 이름에 마우스 오른쪽 클릭 → **New Folder**로 `boards` 폴더를 만듭니다.
6. `boards` 폴더에 오른쪽 클릭 → **New File**로 `nrf54lm20dk_nrf54lm20a_cpuapp.overlay` 파일을 만들고, 아래 내용을 \*\*통째로 복사해 붙여 넣은 뒤 저장(Ctrl+S)\*\*합니다.
7. 붙여 넣은 내용에서 `<&gpio1 4` 부분만 적어 둔 GPIO A 핀에 맞게 고칩니다. 핀 이름 `P1.04`는 `&gpio1 4`, `P0.07`이면 `&gpio0 7`, `P2.10`이면 `&gpio2 10`처럼 **P 뒤 첫 숫자는 gpio 번호, 점 뒤 숫자는 그대로** 씁니다.

```dts
/ {
    aliases {
        led0 = &relay_fan;
    };
    relays {
        compatible = "gpio-leds";
        relay_fan: relay_fan {
            gpios = <&gpio1 4 GPIO_ACTIVE_HIGH>;  /* 고른 핀으로 변경 */
        };
    };
};
```

8. `src/main.c` 파일을 열고 `1000`이라고 적힌 숫자(깜빡이는 간격)를 `2000`으로 바꿔 저장합니다. 소리를 듣기 쉬워집니다.
9. 새 파일을 만들었으니 1단계 8번처럼 **빌드 설정을 다시 만들거나(Add build configuration)** 기존 설정에서 **Pristine Build**를 누른 뒤, **Flash**를 누릅니다.
10. DK 전원 스위치를 켭니다.

**이렇게 되면 성공:** 2초마다 "딸깍" 소리가 나고, 릴레이 보드의 작은 불빛이 켜졌다 꺼졌다를 반복합니다. 끝나면 GPIO A, B 핀 이름을 5단계 담당에게 알려 줍니다.

**안 되면:** 소리가 아예 안 나면 빨강(5V)과 검정(GND) 선이 맞게 꽂혔는지 봅니다. 계속 켜진 채로 있으면 4번의 캡이 L 쪽에 있는 것입니다.

## 5단계 · 판단 프로그램 넣기 (약 2시간)

**목표:** 노트북에서 "방 24도, 습도 45%, 벽 15.5도" 같은 숫자를 DK에 보내면, DK가 스스로 위험한지 계산해서 **LED1(가습기), LED2(선풍기), 릴레이 딸깍**을 알맞게 켜고 끄게 만드는 것입니다. 4단계에서 쓰던 blinky 폴더에 그대로 이어서 합니다.

DK가 하는 계산은 아래 식입니다. 이해하지 않아도 되고, "벽이 차가울수록 벽 표면 습도가 올라간다"는 것만 알면 됩니다.

```latex
P_{sat}(T) = 6.112 \exp\left(\frac{17.62\,T}{243.12 + T}\right), \qquad RH_{surface} = RH_{room} \cdot \frac{P_{sat}(T_{room})}{P_{sat}(T_{wall})}
```

**파일 4개를 만들거나 고칩니다.** 만드는 법은 4단계 5\~6번과 같습니다. VS Code 탐색기에서 `src` 폴더에 오른쪽 클릭 → **New File** → 이름 입력 → 아래 내용 통째로 붙여 넣기 → **Ctrl+S**로 저장.

**파일 ① `src/decision.h` (새로 만들기)**

```c
#pragma once
#include <stdbool.h>
#ifdef __cplusplus
extern "C" {
#endif
struct inputs { float room_t, room_rh, wall_t, bed_rh; };
extern struct inputs g_in;
float surface_rh(void);
void decision_start(void);
void outputs_apply(bool humid, bool fan);  /* 5단계: GPIO, 6단계: Matter */
void inputs_changed(void);                 /* 5단계: 빈 함수, 6단계: 센서 속성 갱신 */
#ifdef __cplusplus
}
#endif
```

**파일 ② `src/decision.c` (새로 만들기)** · 판단 규칙이 들어 있는 핵심 파일입니다. 75%가 되면 가습기를 끄고 0.5초 뒤 선풍기를 켜고, 70% 아래로 내려가면 선풍기를 먼저 끈 뒤 가습기를 다시 켭니다.

```c
#include <zephyr/kernel.h>
#include <zephyr/shell/shell.h>
#include <math.h>
#include <stdlib.h>
#include "decision.h"

struct inputs g_in = { 24.0f, 45.0f, 24.0f, 50.0f };
static bool humid_on = true, fan_on = false;
static int64_t last_change;
static int hold_ms = 10000;               /* 시연 10초, 실제 60초 */

#define ON_TH  75.0f
#define OFF_TH 70.0f

static float psat(float t) { return 6.112f * expf(17.62f * t / (243.12f + t)); }
float surface_rh(void) { return g_in.room_rh * psat(g_in.room_t) / psat(g_in.wall_t); }

static void set_state(bool h, bool f, const char *why)
{
    if (h && f) return;                   /* 동시 가동 금지 */
    humid_on = h; fan_on = f;
    last_change = k_uptime_get();
    outputs_apply(humid_on, fan_on);
    printk("EVT humid=%d fan=%d srh=%.1f why=%s\n", h, f, (double)surface_rh(), why);
}

static void tick(struct k_work *w);
static K_WORK_DELAYABLE_DEFINE(tick_work, tick);

static void tick(struct k_work *w)
{
    float s = surface_rh();
    bool held = (k_uptime_get() - last_change) >= hold_ms;

    if (s >= ON_TH && humid_on) {
        set_state(false, false, "srh>=75 humid_off");
    } else if (s >= ON_TH && !fan_on) {
        set_state(false, true, "srh>=75 fan_on");       /* 0.5초 뒤 */
    } else if (s < OFF_TH && fan_on && held) {
        set_state(false, false, "srh<70 fan_off_first");
    } else if (s < OFF_TH && !fan_on && !humid_on && held) {
        set_state(true, false, "srh<70 stable humid_on");
    }
    printk("VAL srh=%.1f humid=%d fan=%d\n", (double)s, humid_on, fan_on);
    k_work_schedule(&tick_work, K_MSEC(500));
}

void decision_start(void)
{
    set_state(true, false, "boot");
    k_work_schedule(&tick_work, K_NO_WAIT);
}

static int cmd_sim(const struct shell *sh, size_t argc, char **argv)
{
    g_in.room_t  = strtof(argv[1], NULL);
    g_in.room_rh = strtof(argv[2], NULL);
    g_in.wall_t  = strtof(argv[3], NULL);
    g_in.bed_rh  = strtof(argv[4], NULL);
    inputs_changed();
    return 0;
}
SHELL_CMD_ARG_REGISTER(sim, NULL, "sim <room_t> <room_rh> <wall_t> <bed_rh>", cmd_sim, 5, 0);

static int cmd_hold(const struct shell *sh, size_t argc, char **argv)
{
    hold_ms = atoi(argv[1]) * 1000;
    shell_print(sh, "hold=%d s", hold_ms / 1000);
    return 0;
}
SHELL_CMD_ARG_REGISTER(hold, NULL, "hold <sec>", cmd_hold, 2, 0);
```

**파일 ③ `src/main.c` (원래 있던 내용을 전부 지우고 바꾸기)** · Ctrl+A로 전체 선택 → Delete → 아래 내용 붙여 넣기 → 저장.

붙여 넣기 전에, 4단계에서 만든 `boards/...overlay` 파일을 열어 `led0 = &relay_fan;` 줄을 `relay-fan = &relay_fan;`으로 고치고 저장합니다. 이제 DK 불빛 LED1이 가습기, LED2가 선풍기를 뜻하고, 릴레이는 선풍기와 같이 움직입니다.

```c
#include <zephyr/kernel.h>
#include <zephyr/drivers/gpio.h>
#include "decision.h"

static const struct gpio_dt_spec humid_led = GPIO_DT_SPEC_GET(DT_ALIAS(led1), gpios);
static const struct gpio_dt_spec fan_led   = GPIO_DT_SPEC_GET(DT_ALIAS(led2), gpios);
static const struct gpio_dt_spec fan_relay = GPIO_DT_SPEC_GET(DT_ALIAS(relay_fan), gpios);

void outputs_apply(bool h, bool f)
{
    gpio_pin_set_dt(&humid_led, h);   /* LED1 = 가습기 */
    gpio_pin_set_dt(&fan_led, f);     /* LED2 = 선풍기 */
    gpio_pin_set_dt(&fan_relay, f);   /* 딸깍 */
}
void inputs_changed(void) {}

int main(void)
{
    gpio_pin_configure_dt(&humid_led, GPIO_OUTPUT_INACTIVE);
    gpio_pin_configure_dt(&fan_led, GPIO_OUTPUT_INACTIVE);
    gpio_pin_configure_dt(&fan_relay, GPIO_OUTPUT_INACTIVE);
    decision_start();
    return 0;
}
```

**마지막으로 `CMakeLists.txt` 한 줄 고치기** · blinky 폴더 바로 아래에 있습니다. `target_sources(app PRIVATE src/main.c)` 줄을 찾아 `target_sources(app PRIVATE src/main.c src/decision.c)`로 바꾸고 저장합니다.

그다음 **Pristine Build**(깨끗하게 다시 빌드) → **Flash**를 누릅니다.

**시험하기:** Serial Terminal에서 적어 둔 포트를 열고, 아래 왼쪽 칸의 명령을 **한 줄씩 그대로 입력하고 Enter**를 누릅니다. 줄마다 오른쪽 칸처럼 되는지 확인합니다. 창에 `VAL ...` 줄이 0.5초마다 계속 올라오는 건 정상입니다.

| 명령 | 표면 습도 (계산값) | 기대 동작 |
| --- | --- | --- |
| `sim 24 45 24 50` | 45% | 가습 ON, 선풍 OFF |
| `sim 24 45 16.5 50` | 약 72% | 변화 없음 (70\~75% 사이) |
| `sim 24 45 15.5 50` | 약 76% | 가습 OFF → 0.5초 뒤 딸깍, 선풍 ON |
| `sim 24 45 17 50` | 약 69% | 10초 뒤 선풍 OFF → 다시 10초 뒤 가습 ON |
| `sim 24 45 6 50` | 100% 초과 | 선풍 ON 유지 (결로 구간) |

명령의 숫자 네 개는 차례로 **방 온도, 방 습도, 벽 온도, 침구 습도**입니다. 표에서 "선풍 ON"은 LED2가 켜지고 딸깍 소리가 나는 것을 뜻합니다.

**이렇게 되면 성공:** 다섯 줄을 차례로 넣었을 때 LED1, LED2, 딸깍이 표대로 움직이고, 바뀔 때마다 `EVT ...`로 시작하는 줄에 이유가 찍힙니다.

**안 되면:** 빌드할 때 빨간 오류가 나면 파일 이름과 위치(`src` 안인지)를 다시 확인합니다. 창에 숫자 대신 `%f`가 보이면 파일 ④의 네 줄이 빠진 것입니다. `sim`을 입력해도 반응이 없으면 Enter를 쳤는지, 포트가 맞는지 확인합니다.

## 6단계 · 앱과 판단 프로그램 합치기 (약 2시간)

**목표:** 3단계의 전구 예제(앱과 연결된 것)에 5단계의 판단 프로그램을 넣어서, **DK가 위험하다고 판단하면 딸깍과 함께 휴대폰 앱의 기기도 "켜짐"으로 바뀌게** 만드는 것입니다. 앱의 전구 기기가 곧 "선풍기" 역할을 합니다.

이 단계는 3단계와 5단계가 모두 성공한 뒤에 합니다. 작업은 3단계의 `light_bulb` 폴더에서 합니다.

**가. 파일 옮기기**

1. 5단계의 `src/decision.h`, `src/decision.c` 두 파일을 복사해서 `light_bulb/src` 폴더에 붙여 넣습니다(윈도우 탐색기에서 복사·붙여넣기).
2. 4단계에서 만든 `boards` 폴더를 통째로 복사해 `light_bulb` 폴더 안에 붙여 넣습니다. 같은 이름 폴더가 이미 있으면 그 안에 `.overlay` 파일 내용을 이어 붙입니다.
3. `light_bulb/prj.conf` 맨 아래에 5단계 파일 ④의 네 줄을 똑같이 추가합니다.
4. `light_bulb/CMakeLists.txt`에서 `target_sources(app PRIVATE` 로 시작하는 줄을 찾아, 괄호 안 마지막에 `  src/decision.c src/outputs.cpp `를 띄어쓰기 한 칸 두고 추가합니다.

**나. 새 파일 하나 만들기**

5. `light_bulb/src`에 `outputs.cpp` 파일을 새로 만들고 아래 내용을 통째로 붙여 넣고 저장합니다. 노드가 판단한 결과를 앱의 기기 상태로 보내고, 가습기 LED와 릴레이를 움직이는 파일입니다.

```cpp
#include <zephyr/drivers/gpio.h>
#include <app-common/zap-generated/attributes/Accessors.h>
#include <platform/CHIPDeviceLayer.h>
#include "decision.h"

using namespace chip::app::Clusters;

static const struct gpio_dt_spec humid_led = GPIO_DT_SPEC_GET(DT_ALIAS(led1), gpios);
static const struct gpio_dt_spec fan_relay = GPIO_DT_SPEC_GET(DT_ALIAS(relay_fan), gpios);
static bool s_fan;

void outputs_init()
{
    gpio_pin_configure_dt(&humid_led, GPIO_OUTPUT_INACTIVE);
    gpio_pin_configure_dt(&fan_relay, GPIO_OUTPUT_INACTIVE);
    decision_start();
}

void fan_relay_set(bool on) { gpio_pin_set_dt(&fan_relay, on); }

static void SetFanWork(intptr_t) { OnOff::Attributes::OnOff::Set(1, s_fan); }

extern "C" void outputs_apply(bool humid, bool fan)
{
    gpio_pin_set_dt(&humid_led, humid);      /* LED1 = 가습기 */
    s_fan = fan;                             /* 앱의 전구 = 선풍기 */
    chip::DeviceLayer::PlatformMgr().ScheduleWork(SetFanWork);
}

extern "C" void inputs_changed(void) {}
```

### (선택) 방법 B · 시간이 남을 때만, 박건우 담당

앱에 방 온도·습도, 벽 온도, 침구 습도 숫자 4개와 가습기·선풍기 스위치 2개를 모두 보여주는 확장판입니다. 프로젝트 폴더에서 `west zap-gui`로 기기 구성을 아래처럼 바꾼 뒤 `west zap-generate`로 코드를 다시 만들고, 앱에서 기기를 지우고 다시 등록해야 합니다.

| 번호(EP) | 기기 종류 | 앱에 보이는 값 |
| --- | --- | --- |
| 1 | Temperature Sensor | 방 온도 |
| 2 | Humidity Sensor | 방 습도 |
| 3 | Temperature Sensor | 벽 표면 온도 |
| 4 | Humidity Sensor | 침구 습도 |
| 5 | On/Off Plug-in Unit | 가습기 |
| 6 | On/Off Plug-in Unit | 선풍기 |

숫자를 앱에 올리는 코드는 아래와 같고, `outputs.cpp`의 `inputs_changed()`를 이것으로 바꿉니다. 온도와 습도는 100을 곱한 정수로 보냅니다.

```cpp
static void PushSensorsWork(intptr_t)
{
    TemperatureMeasurement::Attributes::MeasuredValue::Set(1, (int16_t)(g_in.room_t * 100));
    RelativeHumidityMeasurement::Attributes::MeasuredValue::Set(2, (uint16_t)(g_in.room_rh * 100));
    TemperatureMeasurement::Attributes::MeasuredValue::Set(3, (int16_t)(g_in.wall_t * 100));
    RelativeHumidityMeasurement::Attributes::MeasuredValue::Set(4, (uint16_t)(g_in.bed_rh * 100));
}

extern "C" void inputs_changed(void)
{
    chip::DeviceLayer::PlatformMgr().ScheduleWork(PushSensorsWork);
}
```

방법 B에서는 `outputs_apply()`가 5번(가습기)과 6번(선풍기)을 모두 바꾸고, `zcl_callbacks.cpp`에서 6번이 켜지면 릴레이가 움직이도록 번호만 바꿔 주면 됩니다.

**시연 중 주의:** 노드가 자동으로 판단하는 동안에는 앱의 버튼을 직접 누르지 않습니다. 누르면 노드와 앱의 상태가 잠깐 어긋날 수 있습니다.

## 7단계 · 시연 화면(시뮬레이터) 만들기 (약 30분)

**목표:** 5단계에서 손으로 치던 `sim` 명령을, **슬라이더와 버튼이 있는 화면**에서 보내게 만드는 것입니다. 심사위원 앞에서는 이 화면만 씁니다. 화면에 뜨는 "벽 표면 습도"는 노트북이 계산한 게 아니라 **DK가 계산해서 보낸 값**입니다.

1. 노트북 바탕화면에 `sim` 폴더를 만듭니다.
2. VS Code에서 **File → New Text File**을 누르고, 아래 코드를 **통째로 복사해 붙여 넣은 뒤** **File → Save As**로 `sim` 폴더 안에 `sim.html`이라는 이름으로 저장합니다.
3. Serial Terminal과 VS Code의 시리얼 창을 **모두 닫습니다.** DK와 대화하는 창은 한 번에 하나만 열 수 있습니다.

5. 화면 왼쪽 위 **포트 연결** 버튼을 누르고, 목록에서 1단계에 적어 둔 포트를 골라 **연결**을 누릅니다.

**이렇게 되면 성공:** 시나리오 버튼을 누르면 왼쪽 "실내 습도"는 45%에 그대로 있고 가운데 "벽 표면 습도"만 올라가다가, 75%에서 빨간색으로 바뀌면서 딸깍 소리가 나고 "선풍기 ON"으로 바뀝니다. 아래 검은 창에는 바뀐 이유가 한 줄씩 찍힙니다. 3미터 떨어져서 숫자가 읽히는지도 봅니다. 작으면 Chrome에서 \*\*Ctrl 와 +\*\*로 확대합니다.

**속도 조절:** 시나리오가 대사보다 너무 빠르거나 느리면, 코드에서 `t -= 0.4`의 0.4를 줄이면 느려지고 늘리면 빨라집니다.
